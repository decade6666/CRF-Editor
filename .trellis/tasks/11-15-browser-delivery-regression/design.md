# C5 Design — Rendered Acceptance, Administrator and Owner Contexts

## Method / Isolation

Chinese checked-in checklist (proposed `docs/testing/versioned-delivery-acceptance.md`) plus private local evidence when separately authorized. Existing DevTools only, no Playwright/runner/dependency/test/CI change. Node/vitest/API/crash tests stay separate.

`new_page.isolatedContext` schema supports named cookie/storage isolation; recheck live connection and actual isolation at execution. Owner A/B establish independent ordinary editor revisions; admin C manages another-owned project; non-admin D tests prohibited history/backup surfaces. Disposable backend/build with independent DB/uploads/temp/backup/control/config/loopback ports and permitted identities, never main assets/real service/systemd/8888. Temporary credentials require formal permission and private handling. Full recovery additionally needs specifically approved destructive disposable setup; inability to drain/restart its own process safely is a blocker.

Desktop plus 390px viewport. Existing VITE_BASE_PATH `/crf/` build and approved disposable prefix-stripping proxy only; no production nginx edits or new packages. Missing proxy/context/permissions/runtime reported exactly, no API-only or Word/WPS visual substitution.

## Evidence / Cleanup

Record scenario, code revision/setup/zone/viewport/base path, exact steps/expectation/actual/timestamp and private evidence paths. DOM/screenshots plus redacted network/console, downloaded byte checksums/authorized document assertions. Never expose auth state/raw headers/password/token values or publish evidence. Pause rather than improvise when login/connection/permissions/proxy/recovery runtime blocks a scenario.

Only task-owned disposable artifacts; cleanup list requires applicable approval, not arbitrary reset/delete. Repeat core cases from fresh state. Defects return to owning sibling; no product source/migration fixes in C5 and no service/browser starts during planning.
