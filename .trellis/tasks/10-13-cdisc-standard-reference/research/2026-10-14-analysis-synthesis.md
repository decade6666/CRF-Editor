## 二、实证地基事实（应直接更新进 PRD 的部分）

1. **`Form.domain` 后端全通、只缺前端入口**（4/4 确认）：models/schemas/routers 均已支持，`export_service.py:774` 已在 aCRF 消费它——补入口是纯前端改动。
2. **COSMoS 实际有 4 个 CSV**，PRD 少列了 `cdisc_biomedical_concepts_hierarchy_latest.csv`（可直接支撑概念树）。
3. **真实数据规模**（fable 流式实测）：SDTM 特化 13,922 行×32 列、32 个域；CRF 特化（草案）2,073 行、仅 16 个域；BC 6,306 行、1,475 个概念。SDTM 正式版数据量意味着**查询弹窗不能照抄现有"整表下发"模式，需服务端分页**。
4. **本地模板库现状**（fable 只读统计）：54 张表单 **domain 100% 空**（aCRF 表单级标注实际从未出现过）；424 个字段定义里**仅 118/398（约 3 成）编号能精确对上标准**；标签 516/517 是中文；52/54 张表单字段 OID 前缀与表单前缀高度一致（域建议可据此推断）；单位以"克/支/粒"类中文为主。
   → 推论：**"未覆盖"会是徽标的大多数状态**，提示必须中性灰措辞；**中文别名是能不能用的命门**。
5. **许可有两处空白/冲突**：COSMoS README 没写明导出 CSV 是否属 CC-BY-4.0；OpenStudyBuilder 的 `import_standards/` 是 **GPLv3**，本项目是 **PolyForm Strict**——只能借鉴设计，不能复制代码（fable 还发现其 db 组件两份许可文件互相矛盾）。
6. **`latest` 文件内 package_date 混有 7 种日期**（最新 2026-07-14），archive 目录 2025-04 起才有 CSV——版本管理要按行级日期而不是文件名。
7. CRF 草案的 `completion_instructions` 列**全空**——不要承诺"填写指南"类功能。

## 四、分歧点与倾向

1. **域编辑是否进 MVP**：opus 主张第一期纯只读、域编辑单独确认；其余三路建议纳入。**倾向：纳入**——后端已全通、实测 domain 100% 空证明刚需；验收必须覆盖"填了 domain 后 aCRF 立即多出表单级标注"联动。
2. **查询下发方式**：sonnet 认为整表下发可行，fable 实测 13,922 行后反对。**倾向：服务端分页**（有数据支撑）。
3. **aCRF 增强**：haiku 想让导出/预览直接显示标准标注文本；opus/fable 判为越界灰区（映射语义 + 监管交付物 + 4.6cm 单行放不下）。**倾向：只做预览层只读参考，导出侧不动**；导出富化需先决策"持久化字段-概念关联"（fable X1）。
4. **就绪度摘要形态**：fable 指出附页表格会破坏预览/导出 parity 校验（`word_table_parity.py` 把最后表单标题后的所有表格都算进该表单）。**倾向：独立报告弹窗/独立文档，绝不进正文**。
5. **草案数据默认开关**：opus/fable 主张默认关；sonnet 主张混排+状态列。**倾向：混排+逐条状态列**（草案占 CRF 特化全部，默认关等于半残），但"疑似不匹配"判定只用正式数据。

## 五、汇总 MVP 建议（四路收敛版）

```
M0  数据底座：离线构建脚本 → 独立只读库 + 配置项 + 署名/草案标识（含第 4 个层级 CSV）
M1  查询：标准查询弹窗（服务端分页）+ 概念详情卡 + 域目录（内置中文域名 = 最小别名集）
M2  域入口：表单属性卡 domain 输入 + 域联想 + 前缀域建议【需用户确认】
M3  徽标：字段标准对照（三态、中性灰、草案标记、与换绑自动完成隔离）
—— 明确推迟：中文别名维护界面、全部报告/体检、豁免、一切写入型、导入导出改动、AI ——
```

MVP 验收基线（可测条目）：未配置标准库时优雅降级且错误不含文件路径；搜 `VSORRES` 返回多个概念并显示版本/日期/正式草案；域建议前缀混合时显示"不确定"；任何徽标交互后 `variable_name` 不变、保存不受影响；页脚 CC-BY 署名。

## 六、待用户拍板的决策点

1. **MVP 是否含域编辑入口（M2）**？— 主会话建议含。
2. **domain 格式**：单值 / 多值 / 自由文本？— 建议单值 + strip 规范化，非标准值警告但允许保存。
3. **中文别名策略**：MVP 只做内置域名对照 + 后续"模板库种子别名"？还是一开始建维护界面？— 建议前者。
4. **数据接入方式**：离线脚本预构建 `.db` 随包分发 vs 管理员运行时导入 CSV？— 倾向管理员配置路径 + 导入（对齐 `_validate_template_path` 白名单先例）。
5. **COSMoS CSV 的许可核实**：需人工核对，多路标记为"实施前必须完成"。
