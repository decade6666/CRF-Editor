# 被引用对象删除拦截与批量删除分组

## Goal

单位 / 字段 / 表单被引用时，删除行为与字典一致：弹窗列出引用位置并拒绝删除，必须先解除引用。字典 / 单位 / 字段 / 表单四类对象的批量删除改为分组处理：被引用的部分只提醒、不可删除；未被引用的部分由用户确认后删除。

## Background（2026-10-09 基于 main `f68ebe1` 核实）

- 字典（`CodelistsTab.vue` `delCl`）/ 单位（`UnitsTab.vue` `del`）：单删已是「查引用 → 有引用则 `ElMessageBox.alert(…, '无法删除')`」；批量删除只要有一项被引用就整批拒绝。
- 字段（`FieldsTab.vue` `del` / `batchDelFields`）、表单（`FormDesignerTab.vue` `delForm` / `batchDelForms`）：前端提示「将同时从表单 / 访视中删除，确认删除？」，用户确认后后端返回 409（「该字段被表单引用，无法删除」/「该表单被访视引用，无法删除」，自项目初始化即存在），用户只看到一条报错。
- 后端删除守卫（409）的引用口径：字典 / 单位 = 任意 `FieldDefinition.codelist_id / unit_id`（包括未放入任何表单的字段库字段）；字段 = 任意 `FormField`；表单 = 任意 `VisitForm`。
- 字典 / 单位的 `references` / `batch-references` 只返回已放入表单的字段（内连接 `FormField`），与删除守卫口径不一致：只被「字段库中、未放入表单」的字段引用时，前端判为未引用，确认后被后端 409 拒绝。批量分组如果沿用这个口径，会把这类对象误分到「可删除」组，导致整批删除失败。
- 这两个引用接口的默认响应还被「修改字典 / 选项 / 单位」「字段库与设计器快速编辑字典」的影响提醒使用；进行中的 `10-08-shared-rule-convergence` 任务正在抽取快速编辑字典弹窗，默认响应必须保持不变。

## Requirements

- R1 单删拦截：字典、单位、字段、表单单个删除时，若被引用，弹出「无法删除」提醒并列出引用位置，不提供删除确认，也不发删除请求；未被引用时保持现有的单次确认后删除。提醒文案：
  - 字典：`该字典被以下字段引用，需先解除相关字段的引用：`
  - 单位：`该单位被以下字段引用，需先解除相关字段的引用：`
  - 字段：`该字段被以下表单引用，需先从相关表单中移除该字段：`
  - 表单：`该表单被以下访视引用，需先从相关访视中移除该表单：`
- R2 批量分组：四类对象的批量删除按引用分成两组，在同一个弹窗里分两段显示：
  - 上段列出被引用的对象及引用位置，只提醒、不可删除；
  - 下段列出未被引用的对象，询问是否删除；确认后只删除这一组；
  - 全部被引用：只显示上段，按钮为「知道了」，不发删除请求；
  - 全部未被引用：保持现有确认框「确认删除选中的 N 个X？」；
  - 混合情况删除成功后提示「已删除 N 个X，M 个被引用的X未删除」。
- R3 引用口径一致：删除流程使用的引用查询必须与后端删除守卫口径完全一致。字典 / 单位的删除检查要把「仅在字段库、未放入表单」的字段也算作引用，显示为 `字段库-字段名(变量名)`。
- R4 以下行为保持不变：
  - 修改字典 / 选项 / 单位、字段库快速编辑字典、设计器快速编辑字典时的「影响提醒」口径与文案（引用接口默认响应不变）；
  - 后端删除守卫（409 与文案），作为并发兜底；
  - 字段属性修改的「多表单影响提醒」（被 2 个及以上表单引用才提示）；
  - 访视删除、选项删除、设计器内移除字段实例、项目删除等其他删除路径。
- R5 安全补充（审查中核实的原有缺陷）：字典单项引用查询必须先检查当前用户的项目归属，再检查字典与项目的对应关系；其他用户查询该项目时，默认模式和 `include_unplaced=true` 模式均返回 403，不泄露字段信息。合法拥有者的默认响应行集合不变。
- R6 经用户授权的同类漏洞修复：字典选项的新增、修改、删除、批量删除、重排序五个子资源端点，必须先校验项目归属，再校验字典/选项归属；不能仅依赖登录认证或字典属于 path project。有效拥有者的既有响应码、删除/排序语义不变。units / fields / visits 路由已完成只读审计，无需改动。

## Acceptance Criteria

- [ ] AC1 字段被任一表单引用时，单删弹出「无法删除」并列出表单（去重），不发删除请求；未被引用时单次确认后删除。
- [ ] AC2 表单被任一访视引用时，单删弹出「无法删除」并列出访视，不发删除请求；未被引用时单次确认后删除。
- [ ] AC3 字典 / 单位只被字段库中未放入表单的字段引用时，单删同样弹出「无法删除」，并列出 `字段库-字段名(变量名)`。
- [ ] AC4 四类批量删除：混合选择时一个弹窗两段显示，确认后批量删除请求只包含未被引用的 id 且成功；全部被引用时只提醒、不发请求；全部未被引用时保持原确认文案。
- [ ] AC5 引用接口不带新参数时，返回内容与改动前一致（同样的行集合）；新参数只作用于字典 / 单位的四个引用接口；跨项目隔离不回退。
- [ ] AC6 后端契约测试锁定：四类对象「批量引用结果的 key 集合 == 删除守卫会拒绝的 id 集合」；对未被引用 id 的批量删除成功，对被引用 id 的批量删除仍返回 409。
- [ ] AC7 前后端全量测试、lint、build 通过；浏览器实测四类对象的单删、批量混合、全部被引用、全部未被引用路径。
- [ ] AC8 文档同步：前端组件规范「删除确认」场景、跨栈契约新增章节、根与模块 `CLAUDE.md` 变更记录、README 功能描述、`.claude/index.json`。
- [ ] AC9 字典单项引用查询：其他用户访问默认 / 包含未放置字段两种模式均为 403；拥有者正常返回 200，自己项目中的不存在字典仍为 404，字典与请求项目不匹配仍为 403。生产部署未获授权，不能将本地修复描述为线上修复。
- [ ] AC10 字典选项 5 个子资源端点：非拥有者对他人项目返回 403 且不改变选项数据；拥有者保留正常成功码/语义；自己项目不存在字典仍为 404、字典与 path project 不匹配仍为 403。缺失的守卫确认为预存缺陷，修复不视为既有合法行为变更。

## Out of Scope

- 后端批量删除改为部分删除或返回跳过明细（保持全有或全无的 409）。
- 「解除引用」的快捷操作（如一键从表单 / 访视移除）。
- 隐藏类型（标签 / 日志行）字段定义引用字典或单位的边缘情况专门处理（如实列出即可）。

## 跟进（Opus 审查，2026-10-10，用户已授权安全修复与提交合并）

- R7 批量删除引用守卫限定本项目范围（安全修复）：字典 / 单位 / 字段 / 表单四个 batch-delete 接口的 409 引用预检只针对属于路径项目的 id；他人项目或不存在的 id 与 `batch_delete(..., project_id=...)` 一样静默忽略（返回 200 与更小的 `deleted`），不得改成 403 / 404。修复后外人无法再用 409 / 200 的差别判断他人对象是否被引用。
- R8 回归测试补强：以下任一回归都必须让测试失败——混合弹窗取消仍删除；全部被引用仍发删除请求；未被引用的单删被拦截；归属校验顺序调反（外人 + 他人项目 + 不存在的字典 id 必须 403）；AC6 逐 id 划分失效；选项「不属于该字典」检查失效；批删 409 失败路径、部分删除后保留选中、部分删除提示触发条件、字段库快速编辑字典不带新参数。
- R9 文档与索引更正：恢复 `.claude/index.json` 后端 `commands`；规格示例的已删除数取后端 `deleted`；auth-security 规格与 `verify_project_owner` 实际契约一致（外人 403、自己缺失 404、不过滤软删除）；服务 docstring 改为「行集合一致」。

- [ ] AC11 四个 batch-delete 接口：他人被引用 / 未被引用的 id 均返回 200 `{"deleted": 0}` 且他人数据不变；自己未引用 + 他人被引用的混合请求只删除自己的；自己被引用的仍 409；修复前记录 RED（409）。
- [ ] AC12 每条新增回归测试都在临时副本中证明能杀死对应变异；前后端全量测试、lint、build、ruff 通过。
