# C6 Design — Bounded Data History and Atomic Restoration

## Proposal / Dependencies

D8 supersedes owner-operated history/repair and fixed count/100MB policy, while retaining data-only capture and private-history integrity. Keep FastAPI/SQLAlchemy/SQLite, existing in-process jobs and Vue/useApi. C4 supplies physical state, C2 schema/capabilities, C3 pure diff. C6 supplies common admin quick-history/policy host before C7 extends system backup and C8 system recovery; no new scheduler/queue/dependency/Agent tool/DSL.

## Typed Data and Capacity Accounting

Extend the C2 private history model/registry with automatic kind and `capture_reason` (`periodic` or `before_restore`), usable data-only state, schema/codec version, capture time, source design revision, content hash, stored/expanded byte counts and capture capabilities. Manual completion retains its fixed artifact requirements. Automatic/protection rows contain no file bytes or browser-local layout; a historical file reference, if recorded for provenance, is explicitly non-restorable.

Propose canonical UTF-8 JSON plus standard-library lossless zlib compression in SQLite, not sidecar snapshot files. Hash canonical expanded server-design bytes under the schema contract, keeping source entity/reference keys and legacy/null values explicit; exclude capture timestamps/history IDs, auth/private state and volatile bookkeeping. Use codec/schema/hash integrity checks and reviewed expanded-size/row/depth/time bounds before parsing/restoration; compressed-size budget alone must not permit unbounded decompression. Compression/limits are review proposals, not measured ratios or relaxed MCP caps.

Default automatic age retention is seven days. Independent age/size switches, size disabled initially; when configured, use exact stored payload bytes (proposed decimal MB labels), not counts or old 100MB defaults. Automatic periodic records only are eligible; protected pre-repair records have manual-action origin and need explicit admin deletion. Review/status/replay metadata is separately bounded overhead; DB pages/WAL/index/free pages, protected/manual histories and C7 system sets add space. No live VACUUM or disk-cap claim.

Validate the new payload before eligible cleanup, then insert and age/size cleanup under one transaction with deterministic capture-time/ID order and current-origin/active-source checks. Failed/oversized capture preserves existing history. Independent age cleanup may run from the administrator-enabled policy when no new capture is due, but never because a failed new capture needs room. Protect active preview/apply/download sources or reject newly missing targets truthfully. Admin policy/preview uses the existing independent-rule pattern, not recycled-project purge.

## Scheduler and Coherent Capture

1. Respect `CRF_DISABLE_BACKGROUND_JOBS`; create one lifespan-managed automatic-history loop when enabled. Proposed startup checks current eligible projects once, then five-minute due checks; no backfilled fictional records for downtime. Interval is scheduling intent, not a hard real-time SLA under load.
2. Reuse worker-thread handoff with a worker-owned Session/connection, never a request dependency or a Session shared across threads. Process active, validly owned projects in bounded batches, one project's failure at a time. Do not wait for browser presence or stop on browser logout.
3. A lightweight persisted design revision may skip needless full reads; when revision changed or no record exists, read owner/lifecycle/revision plus the complete allowlisted graph in one real coherent read snapshot. Canonicalize/compress outside a long writer lock. Dedup by latest automatic captured design content, not a revision/timestamp alone; an edit returning to the same content may be skipped.
4. In a short physical writer transaction, recheck active ownership/state and automatic latest record, insert validated data and apply automatic-only quotas atomically. If live state changed meanwhile, skip/retry on a bounded later check rather than label stale bytes as the latest state. No full-project hash is added to every browser request and no Agent fingerprint cap is changed.
5. Capture/status/history writes do not advance C4 design revision or affect Agent fingerprint. Persist safe last-check/last-success/error metadata separately; distinguish unchanged, disabled, failed and successfully captured. Admin UI may show this metadata, but logs contain only safe IDs/status/counts, never full design/credentials.
6. No overlapping rounds or catch-up queue. On shutdown stop new rounds and drain in-flight thread work before disposing resources: cancelling an await does not kill its SQLite thread. Use existing worker-draining patterns and retained shutdown tests. Recycle/purge and capture compete through current in-transaction checks, not assumptions from enumeration.

## Restore Review and API Boundary

Propose dedicated admin project-history APIs and preview/apply repair, plus common admin age/size policy/status/cleanup preview. Current admin → active project/lifecycle → record membership, not owner-only APIs. Admin can manage another owner's project through this explicit boundary; do not change global owner helpers or Agent scopes. No caller paths/SQL/uploaded snapshots. Closed bounded DTOs, safe Chinese messages/codes, no-store and current-role recheck for every read/replay/download. Ordinary users have no backup/history controls; their usual editing/export stays unchanged.

Before preview, use existing draft/property/busy/annotation guards for the active editor and any relevant project-metadata dirty state. Saving is explicit and may change the revision, requiring a fresh preview. Discard is an explicit user decision, not a side effect of opening history. Cancel/close/failure does not reload/erase input. While a confirmation is active, prevent new initiating-editor commands from racing it; other sessions remain unlocked and are handled by revision checks.

Preview is design/history-write-free apart from bounded private review bookkeeping. Capture current design coherently and use C3 for current-versus-target normalized changes. Show affected project/visit/library/form changes, identity caveats, current file bindings retained, uncaptured browser layout/unsent drafts, quota/protection behavior and the destructive whole-design replacement warning. No original/report generation occurs here. Browser view/comparison can remain useful even when a record is not restorable due to a newer incompatible policy.

Propose a short-lived (10-minute) opaque review binding stored/digested server-side, scoped to current admin/target project (including owner/lifecycle binding), automatic target ID/hash/schema, reviewed current design revision and restore-contract digest. Apply supplies only this binding, stable request identity and the matching C4 precondition. Recheck target presence/integrity and all scope/state/expiry constraints; a newer write or rolled-off target requires review again. Never silently attach a fresh revision to old confirmation.

## Restore Transaction and Scope

Use the C4 physical `BEGIN IMMEDIATE` ownership pattern, not a writer nested inside request `session.begin()`. Parsing/planning may occur before lock, but all authoritative authorization, target/state validation and mutation share the same connection/transaction.

1. Reauthorize current admin/project lifecycle and bind/check the request identity. A completed same-input replay returns the existing committed outcome only after authorization, not another replacement; mismatched identity fails. Unknown/expired outcome never triggers automatic retry.
2. Revalidate the review/target/revision and target payload integrity, allowlist/dependency closure, unique constraints, ordering, reference graph and current restore-contract policy. Capture the actual current committed design and prepare a complete bounded protection payload; it must describe the state being replaced, not a stale browser image.
3. Store the protection record in this transaction, then replace only allowed design data. Never delete/recreate the Project row or invoke project purge/Logo cleanup/import SQL. Preserve live Project ID/owner/lifecycle/creation identity, current timestamps as lifecycle data, revision/history/review/result/private Agent state and current Logo/file bindings/bytes. Restore business design metadata (including CRF version/date) only as explicitly previewed fields, not capture bookkeeping.
4. Reconcile surviving children and create/remove only as necessary in dependency-safe order, with FKs enabled and explicit source→destination maps. Before any ORM delete/flush/autoflush or orphan-cleanup helper can remove a definition, neutralize its nullable `AgentOperation.definition_id` back-pointers in the same authorized transaction so declared `ON DELETE CASCADE` cannot erase operations and their audits. This proposed narrow internal detachment changes only the live relational pointer, not immutable commands/inputs/digests/results or operation/audit IDs; do not retarget historical operations to replacement definitions or disable FKs. Validate historical list/detail/replay projections with detached pointers before start; block restoration if private-history preservation is not proven.

   Preserve OID/legacy values exactly; no authoring uppercase, copy-name defaults, import dedup/renaming or broad repair. Numeric IDs remain implementation keys, not continuity proof; foreign-project rows cannot be overwritten/deleted to reuse a historical ID. Enumerate the still-registered legacy `field` table explicitly because current clone loader/fingerprint omit it; capture/restore its approved compatibility data or reject unsupported nonempty state before writes. Validate the final graph under the reviewed restoration policy, never normalize an incompatible historic graph silently.
5. Advance design revision monotonically. Add one narrow restore-invalidation transition rather than call existing `decide_change(False)`: select same-project shared proposals with approval `pending` or `approved` and `after_fingerprint IS NULL`, including preview rows already `status=done`; move them to a durable rejected state with accurate restore-reason audit. Existing owner rejection requires pending/unexpired/current-fingerprint match and is unsuitable here. Do not change already applied proposal states/after-fingerprints, completed operation results/input identities, original preview replay envelopes or credential hashes. A return to an old content fingerprint cannot revive the retired proposal; applied requests retain replay-before-stale semantics.
6. Persist protected manual-action pre-repair data plus bounded replay/success outcome with target/protection IDs/hashes/resulting revision, and only policy-eligible automatic cleanup, then commit once. Protected data is not in scheduled age/size candidates; finite per-operation space preflight still applies. Any fault rolls back protection/replacement/proposal changes/cleanup/outcome together. A target already evicted before validation rejects apply; an active source is protected through the operation. No old 100-count/100MB rollover or protection expiry is silently retained.
7. Only after confirmed commit, invalidate initiating-project caches and stale async generations, reload current graph/revision, and clear old in-memory undo/redo/obsolete selected IDs. Do not append a whole-project restore as ordinary field undo. On ambiguous response, use bounded same-request result lookup/replay after reauthorization, not a second blind apply or local-success fiction. Other open editors retain their drafts and hit C4 stale protection on writes; no real-time collaboration guarantee.

Existing field restore/import/clone routines provide reviewed primitives only, not their append/merge/dedup/commit/file behavior. Numeric remapping updates numeric graph references; `annotation_positions` keys are field `variable_name` and `_form`, not IDs, so preserve their established validated meaning without inventing ID-key rewriting. Ordinary key validation does not prove every key currently corresponds to a field, and JSON storage may be canonicalized rather than byte-identical. Preserve current project-list `order_index` as navigation state, not form/visit design ordering. Verified source anchors, FK cascades, compatibility-table omissions and the restore-specific Agent transition limit are in parent research evidence.

## Private Lifecycle and Compatibility

- Automatic/protection/review/replay/status state stays system-local and excluded from product exchange/import/copy; C7 faithful system images include recovery-relevant state instead. New copied projects start fresh. New admin control state is not Agent private-table reclassification.
- Soft-delete/recycle retains quick history but excludes capture/repair. Current-admin authorization and explicit ownership/lifecycle binding invalidate stale reviews after transfer, not an owner-only gate. Final purge clears current project-local history safely, never deletes independent sealed C7 full sets. No file rollback here.
- Snapshot codec/schema versions fail closed when unsupported. Historical reads do not rewrite/repair content. A source rollback preserves history; DB rollback/cleanup/deploy and hard deletion require separate approval.
- Bound review/replay metadata with a proposed 10-minute review lifetime and 24-hour/100-result per-project success-replay window, retaining hashes/IDs/outcome only, not duplicate payloads/secrets. After expiry, report uncertain outcome honestly and require reload/review; no Agent result retention/schema changes.

## Verification and Remaining Gates

Real file-backed SQLite races for capture/write, capture/purge, preview/third write, apply/Agent and double confirmation. RED tests for both quotas, protection oversized, bounded decompression/corrupt hashes, FK/order/annotation maps, legacy values, mid-replacement/commit faults, lost-response replay, pending-proposal old-hash cycles, private/file invariants and export/copy stripping. Job enable/disable/worker-drain and Vue dirty/context/reset tests remain separate. C5 B10–B12 verifies real due check and operator-driven restore with permitted disposable resources; synthetic clocks/seeding do not count as browser scheduler evidence.

Review concrete byte convention/codec/input bounds, restoration graph/ID policy, proposal invalidation and review/replay defaults before start. No migrations, source change, file generation, scheduler/capture/retention/restore execution or production access is performed by this design.
