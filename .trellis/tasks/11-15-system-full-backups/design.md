# C7 Design — Sealed Whole-System Backup Groups

## Review Boundary / Storage

Propose one shared engine for scheduled/manual full runs, no new runtime service/dependency. Configure a private local backup root outside DB/uploads/restore targets; catalog, policy, locks and recovery control are separate from immutable sets and excluded from traversal. Opaque server names, directory 0700/file 0600 equivalents, no static serving or caller paths. Existing product export's private-stripping helper must not be called as full backup. Factor a faithful SQLite-copy primitive only if reviewed; ordinary exchange behavior remains unchanged.

Propose self-contained versioned archive/directory sets with a closed manifest: run/source/origin, capture/completion time/zone, schema/app/renderer versions, file sizes/checksums, all captured project IDs/active status, per-project normalized snapshots, generated formal-pair references and recovery DB identity. Hashes detect corruption, not protection against an attacker controlling both trusted catalog/storage. No external upload or unapproved encryption/dependency change; sensitive backup access/security is a mandatory review gate.

## Capture → Render → Seal

1. Current admin authorizes manual request or enabled schedule claims durable local-date/time/zone due identity; same-input replay returns one run. One full run/recovery at a time. A pure process mutex is insufficient across crash/restart; persist phase/outcome outside restored data with bounded metadata.
2. Source-inventory all actual persistent DB and application-managed roots and copy exclusions before GREEN. Do not dump live config/secrets or follow configured external template paths automatically. The artifact is an application-data backup, not a server image; operator must retain compatible app/deployment/secrets separately.
3. Bounded capture barrier gates all relevant browser/Agent/import/upload/Logo/history mutations and background purge/file cleanup, and drains accepted operations/threads before snapshotting. Read-only requests may continue if safe; manual UI warns about temporary write pause. Ensure expiry/revocation/error paths release the barrier. No hard user editing workflow lock is added outside this capture phase.
4. Obtain a faithful SQLite backup and matched safe file copies while quiescent. Handle WAL with SQLite-supported backup, never copy only live main DB or transplant live WAL. Copy only manifest-owned files; no backup recursion, temporary/import/screenshot/secret/env/source content. Complete trusted staged DB is the sole render source. Release live barrier before Word work.
5. Read captured graph for every captured active project, validate dependency/legacy closure, generate fresh dual originals via C2 disposable context and captured Logo/persisted orientation/annotations/automatic layout. No later live file/owner/UI input reads. Capture label distinguishes schedule/manual source and layout; both files validated/checksummed. Build metadata in the staged recovery image/manifest, not overwrite current business design. Recycled/inactive projects remain in copied DB with prior files, without new rendering.
6. C2/C3 reader interface must expose package-owned snapshots/originals from the sealed manifest/image even before restore, with bounded safe DTOs and no arbitrary SQL/import/migration of external files. History ID binds set+project+record; comparisons remain same-project and no restore extraction API is added. Live project purge cannot erase package content; after full recovery, staged DB archive references and restored files agree.
7. Verify DB integrity/FKs/schema, all required files and pairs, manifest and bytes; publish complete set atomically in private storage and seal catalog record with replay-safe request/run identity. Any failure remains incomplete/unusable and leaves earlier backups/manual archives intact. New set time is capture time, not a false claim of all edits up to render completion. Interrupted staging is observable and cleanup only via known owned paths/policy, not broad directory deletion.

## Schedule / Status Proposals

Extend existing lifespan/disable/worker-owned Session patterns. Use OS local wall-clock for due checks and a monotonic clock for sleeps; display effective zone/next-run, and recompute after timezone/DST/clock changes. Propose at most one startup catch-up for the latest missed local due day (no backlog of fabricated daily sets); distinct manual triggers do not rewrite a scheduled due identity. Persist success/in-progress/failure and bounded retry/backoff; no endless immediate rerender loop. Exact retry/catch-up policy is reviewable; failures remain visible and do not pretend backup freshness. Cancellation drains worker/render subprocess cleanup before releasing locks.

## Cleanup / Size Policy

C6 shared admin policy supports independent age and size rules. Scheduled full/formal group age defaults 30 days; size disabled until set. Define full budget on actual retained set plus any separately owned generated-formal bytes without double-counting shared files. Quick payload budget is separate. Default time-only retention is not a disk cap; manual sets/internal recovery protection/staging/catalog/WAL add space. Include live auto-original storage in inventory if stored outside package.

Age candidates first, then oldest remaining eligible groups until configured byte target; each action rechecks origin/completion/reference/active state. Never touch manual/protection records, latest usable full set, active restore/download/capture sources or another set's files. DB/catalog tombstone before deferred safe unlink; incomplete unlink is observable, never advertise reclaimed bytes before confirmed removal. Self-contained sets mean deleting a live project/current auto archive does not remove retained set dependencies. Retention never uses recycled-project purge. New backup failure cannot trigger pre-deletion to free enough room; space preflight warns/fails rather than sacrificing the last recovery point.

## API / Migration / Tests

Admin-only no-store closed policy/status/list/run/download/delete/cleanup-preview APIs through useApi and admin host. Every operation rechecks current admin including replay/result retrieval, with bounded output and no raw DB/private/credential values. Restrict download to verified set IDs; no arbitrary filesystem archive creation. Policy save/preview displays exact eligible manual-excluded groups/latest-good protections and warnings before effective cleanup.

New private history/catalog metadata excluded from product exchange, raw recovery DB retains business-private data. Root/catalog provisioning, SQLite compatibility and post-restore index reconciliation need current-source review. Source rollback retains all sets.

RED tests: real file-backed SQLite+file race capture barrier; no-strip vs exchange; zero/multiple active project paired render; missing/legacy/Logo/layout faults; copy/render/seal/catalog interruptions; local DST/rollback/restart and manual overlap; age/size/group/reference/download/restore cleanup; no duplicate response-loss run; non-admin/role-loss and path/privacy. Coverage ≥80% without decrease, actual security/parity/diff and C5 B13–B15 evidence. Nothing executes during planning.
