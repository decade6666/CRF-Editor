# frontend Module Notes

> Last updated: 2026-10-26

## Module Responsibilities
- Provide the Vue 3 single-page interface for the CRF editor.
- Manage login, projects, visits, forms, fields, units, dictionaries, settings, and admin pages.
- Handle template import, project import, Word import two-column evidence preview, export, theme switching, and sidebar interaction.
- Provide CRF preview rendering, ordering, cache refresh, field instance quick edit, column width / row height dragging, and session countdown experience.

## Key Entry Points
- `frontend/src/main.js`: creates the Vue app, mounts `App.vue`, and registers Element Plus with the zh-cn locale; it registers no Element Plus icons — every component imports the icons it renders from `@element-plus/icons-vue`.
- `frontend/src/App.vue`: application shell; manages login state, post-login routing through `/api/auth/me`, regular project workbench, standalone admin workbench, import/export, refresh, theme, settings dialog, and password-change dialog. Since the Word-import wizard extraction (task `app-word-import-split`) it no longer owns the wizard state machine: it keeps only `showImportWordDialog` plus the visibility-only `openImportWordDialog()`, mounts `WordImportDialog.vue`, and routes `@open-designer` through the `useDesignerFormSelection` ready bridge. Since `template-import-refresh` (2026-10-16), `executeImport` also routes the first backend-returned `imported_form_ids[0]` through the same bridge after success — guarded by the project id captured at request start (late successes never select across workspaces), absent/empty ids select nothing, and a post-write handoff failure reports 「导入已完成，但展示新表单失败」 instead of an import failure.
- `frontend/src/components/WordImportDialog.vue`: Word-import wizard UI (3 steps + compare mount). Props `modelValue` (Boolean, required) and `projectId` (Number, `null` allowed while mounted); emits `update:modelValue` and `open-designer(formId)`. Owns the dialog template plus the `.form-select-*` / `.docx-ai-global-*` / `.docx-form-*` styles moved verbatim out of the App shell, the async `DocxCompareDialog` mount (keyed by `compareFormData?.index`, `v-if="compareFormData"`), and the `apiUrl()`-wrapped upload `:action`; all state/handlers come from `useWordImport`. The main dialog forwards `:model-value` plus `@update:model-value` only — it deliberately does not forward `@close`, because Element Plus 2.13.2 emits `close` in `beforeLeave` but `update:modelValue(false)` in `afterLeave`, and the old `v-model` reacted only to the latter (forwarding `close` would run the close-branch cleanup mid-transition).
- `frontend/src/composables/useWordImport.js`: per-invocation Word-import state machine (`{ projectId, visible, refreshKey }` Refs) — upload guard (10 MiB) and result handling, AI review polling (3-second `ai_task_id` status GET, merge + `reconcileAcceptedOverrides`), three-level AI suggestion acceptance, `ai_overrides` payload assembly, execute-import, compare open/close, and the `visible` watcher (open = full session reset, close = stop polling + clear compare/accepted state). Registers `onScopeDispose` with an `isDisposed()` guard so an in-flight **AI status** response after unmount never writes AI-review state or reschedules the poll; the upload/execute handlers were moved from the App shell unchanged and are not disposal-guarded. No module-level mutable state (composed from per-invocation factories).
- `frontend/src/composables/useDesignerFormSelection.js`: event-driven ready bridge `useDesignerFormSelection(designerRef)` → `{ requestFormSelection }`; keeps at most one pending form id per invocation (latest wins), calls `selectFormById` immediately when the ref already exposes it, otherwise consumes the pending id via a `watch(designerRef, …)` and clears it before awaiting, so a later designer remount cannot replay it. No timers or polling.
- `frontend/src/composables/useApi.js`: unified requests, error parsing, 401 invalidation handling, GET cache, and automatic invalidation.
- `frontend/src/composables/acrfAnnotationGeometry.js`: shared aCRF annotation geometry constants and unit conversion helpers, mirroring backend export constants and the `posOffset = default + Δy` contract.
- `frontend/src/composables/useAcrfAnnotationDrag.js`: shared aCRF annotation vertical-drag and persisted PATCH queue for `FormDesignerTab.vue` and the visits preview (now hosted by `VisitFormPreviewDialog.vue`).
- `frontend/src/composables/useVisitPreviewAnnotation.js`: per-invocation aCRF annotation glue for `VisitFormPreviewDialog.vue` — target construction (form domain / field OID / inline header), annotation style, drag gate, its own `useAcrfAnnotationDrag` instance, immutable `onPersisted` merge into the dialog's form ref, and injected `onError`. No module-level mutable state (one call = one dialog = one drag instance).
- `frontend/src/composables/useCRFRenderer.js`: unified field rendering, HTML preview, content-driven column width planning, and the codelist-free checkbox (`复选`) control text fallback.
- `frontend/src/composables/formFieldPresentation.js`: presentation-layer rules for field instance display attributes, colors, default values, and related behavior.
- `frontend/src/composables/previewCellRender.js`: shared pure Word-preview cell helpers for FormDesignerTab, the visits preview dialog, and TemplatePreviewDialog (`renderCellHtml`, `getInlineRows`, `getInlineColumnCms`, `getInlineFillChars`, `computeMergeSpans`, `computeLabelValueSpans`, and `getScopedDefaultValue`). `createPreviewCellRenderers` accepts adapters for each host's cell/inline default-value policy, fallback renderer, render groups, and paper orientation; it reuses `useCRFRenderer.js` and `visitPreviewLandscape.js` rather than duplicating algorithms.
- `frontend/src/composables/searchRanking.js`: shared pure helper for user-facing fuzzy search ordering; empty keywords keep source order; ranks by tier (exact > contiguous substring > ordered subsequence > bounded-edit-distance approximate substring), then by match quality, and equal ranks stay stable. Edit distance is enabled by keyword length (1–2 chars: off; 3–5: ≤1 edit; 6+: ≤2 edits with a 0.7 similarity floor); no pinyin, no result truncation, multi-candidate texts supported (legacy concatenated candidates preserved).
- `frontend/src/composables/useOrdinalQuickEdit.js`: shared list ordinal quick-edit helper; double-clicking a visible ordinal cell opens direct target-position input, keeps filter-disabled semantics aligned with drag sorting, and reuses existing reorder endpoints with the common restore-on-failure message.
- `frontend/src/composables/useColumnResize.js`: form designer column width dragging and local persistence coordination; also owns 列宽存储键拼装 / 解析 / 校验 / 旧键迁移（`buildColumnWidthStorageKey` / `parseColumnWidthStorageKey` / `isValidColumnWidthOverrideArray` / `migrateLegacyColumnWidthKey`）以及 Word 导出列宽覆盖收集 `collectColumnWidthOverrides`（原 App.vue 内联实现迁入，严格只读）。
- `frontend/src/composables/useRowResize.js`: Word preview row height dragging, stable row keys, and local persistence.
- `frontend/src/composables/useSessionTimer.js`: JWT `exp` display, near-expiration reminders, and click-to-renew by reusing `/api/auth/me`.
- `frontend/src/composables/formDesignerPreviewModel.js`: derived view-model cache for form designer / template preview, avoiding repeated recalculation for templates.
- `frontend/src/composables/docxAiSuggestionOverrides.js`: pure Word-import AI suggestion acceptance helpers for three-level selection state, suggestion reconciliation after polling, and execute `ai_overrides` payload construction.
- `frontend/src/composables/byteSize.js`: shared byte-size formatting for recycle-bin estimated-size display and cleanup-policy preview/stats.
- `frontend/src/composables/templateFieldSearch.js`: pure helpers for the read-only template field search dialog — field-level candidate texts (OID + label + label_aliases), the source-form-OID candidate extractor (`sources[].form_code`), the four-group ranking wrapper `rankTemplateFieldMatches` (field-strong > form-OID-strong > field-fuzzy > form-OID-fuzzy, composed from the unchanged shared `searchRanking.js` with first-reference dedup), inline source-line text (`form_code form_name（显示为：xx）` / name-only / 仅字段库), format/copy-toast column text, and the 50-per-page pagination constant; data shape comes from `GET /api/template-fields`.
- `frontend/src/composables/clipboardCopy.js`: the only file allowed to touch the system clipboard; secure-context `navigator.clipboard.writeText` first with a readonly-textarea `execCommand('copy')` fallback for plain-HTTP deployments, and an injectable env for node:test.
- `frontend/vite.config.js`: development server, `/api` proxy, and build chunking configuration.

- `src/composables/`: shared logic for API, aCRF annotation geometry/persistence, the visits-preview annotation glue (`useVisitPreviewAnnotation.js`), Word-import AI suggestion acceptance/reconciliation/payload building, the Word-import wizard state machine (`useWordImport.js`), the designer-selection ready bridge (`useDesignerFormSelection.js`), drag ordering, ordinal quick edit, ranked fuzzy search, OID charset validation (`oidValidation.js`, covers form / field / codelist identifiers — codelist option codes are free-form and not covered) plus the Saimeisi edited-OID length policy (`editedOidLengthError`, same file: 8/10-character caps on manually changed field/form OIDs in 赛美斯 projects, compared against an edit-session baseline so unchanged automatic/legacy values stay exempt) and the entry-time `oidMaxLength` helper (conditional maxlength for input-level enforcement), field-library visibility, field-library autocomplete candidates, delete confirmations, reference-aware deletion gating (`referenceDeleteGuard.js`), byte-size formatting, design-notes header summary/tooltip helpers, field rendering, shared preview cell pure helpers, form designer property editing, preview view model, export download state, column width / row height dragging plus column-width key build/parse/validate/migrate, session countdown, designer undo/redo history, visit preview orientation, pane splitting, lazy tab loading, template field search helpers, centralized clipboard copying, and more.

- `components/VisitsTab.vue`: visit structure with a default two-pane list workspace (`workspaceMode: 'list'`: left visit table + right 320px property card for add/edit, OID + name only, sequence managed solely by drag + ordinal quick edit; deleting the selected visit suppresses the table `current-change` re-select so the card returns to its empty state) and an in-page visit-flow workspace (`workspaceMode: 'flow'`) that toggles between a page-inlined visit–form matrix and a single-visit form-maintenance view (`flowView: 'matrix' | 'single'`, small switch); matrix unchecking and single-view removal delete directly without confirmation; visit / visit-form ordering tables with drag + ordinal quick edit. - `components/VisitFormPreviewDialog.vue` (`visits-preview-split`): self-contained single-form preview dialog. Props `modelValue` (Boolean, required), `projectId` (Number, required), `formId` (Number, default `null`); emits only `update:modelValue`; mounted unconditionally (plain mount, no `append-to-body`). On open it resolves the authoritative `FormResponse` through `api.cachedGet('/api/projects/{pid}/forms')` (design_notes / paper_orientation / domain / annotation_positions) before fetching `/api/forms/{id}/fields`, with one request-sequence counter covering both awaits; `@closed` resets state and flushes pending annotation saves. Owns the moved preview template, the eCRF / aCRF view mode (`crf_view_mode`, same persisted key as the designer), `useRowResize` (`toRef(props, 'formId')`) plus its resizer cache, the `DesignerAcrfAnnotation` call sites (8: form ×1 / field ×5 / inline-header ×2), the full-mode paper-title OID badge (`FormPreviewOid.vue` fed by the resolved authoritative form's `code`), and the annotation glue from `useVisitPreviewAnnotation.js`; it injects `editMode` and imports the `Loading` icon it renders (it no longer fails component resolution).
- `components/FieldsTab.vue`: field library maintenance; supports the codelist-free single checkbox type (`复选`) with optional checkbox text that falls back to the default character `✔`. The choice-field option row provides inline 新增字典 / 编辑字典 entries that open the shared `CodelistQuickEditDialog.vue` (endpoints, reference impact confirmation, and dual cache invalidation live in the dialog; the host keeps open guards, the created-codelist rebinding, the `新增成功` close→toast message, and `refreshKey` sync), and the main list supports ordinal quick edit; referenced fields cannot be deleted, and mixed batches delete only unreferenced selections after confirmation. Field saves enforce the Saimeisi manual-OID length policy (8-character cap on manually changed OIDs in 赛美斯 projects; the baseline is captured in `resetProp` — the single initialization seam covering 新增 generated defaults, 编辑 row values, and post-save rehydration — so untouched values stay exempt). The OID input additionally binds a conditional `maxlength` (`oidMaxLength`) so in 赛美斯 projects the 9th character cannot be typed or pasted, while programmatic prefill of long baselines is unaffected.
- `components/FormDesignerTab.vue`: form design, field instance editing/copying (with robust undo/redo replay that mirrors exactly what the forward save wrote, including pure rebinds), explicit property save/cancel with dirty leave guards and reference-aware impact confirmation (the confirm target and the PUT command share one `buildSelectedFieldCommandArgs` decision; a shared definition is written only when the 9 editable keys differ after `normalizeDefinitionPayload` normalization, so pure references and presentation-only saves neither warn nor rewrite), field-library candidate picks that keep the editor's unsaved presentation (font size incl. the `'default'` sentinel, colors, bold) and pending default value / inline mark, full-screen designer form-switch dropdown plus inline form-property card (OID / name / paper orientation) with the same explicit save/dirty-leave pattern, real-time preview, complete-mode eCRF / aCRF preview switching with field OID / form-domain annotation overlays, shared vertical annotation dragging/persistence, column width dragging, quick edit, shared codelist add/edit dialog with host-owned refresh/rebinding, in-memory undo/redo (Undo/Redo buttons + Ctrl+Z / Ctrl+Y), ordinal quick edit for the left-side form list, and checkbox type/text editing; native field-list dragging resolves the drop target by field ID and treats the row-top highlight line as an insertion boundary (`commitFieldDropAtBoundary`, fields land above the target row, with `.ff-drop-end` as the absolute end-of-list boundary since the `designer-field-drag-offset` fix, 2026-10-14); referenced forms cannot be deleted and mixed batch deletion preserves referenced selections. All OID-authoring saves (persisted-field property save, new/copied-field draft save, form create / edit-dialog / inline property save) enforce the Saimeisi manual-OID length policy (field 8 / form 10 in 赛美斯 projects; untouched candidate-rebind OIDs and draft creation-seed baselines (`__labelOidSeed`) are exempt; system-managed 标签 / 日志行 OIDs are skipped; the form edit dialog freezes an open-time OID snapshot in `editFormBaselineCode`, and both form save entries pass `baselineCode` into the shared `persistFormProps`, with the inline pane reading `formPropBaseline.code`). ## Development Conventions
- Put complex reusable logic in `composables/`.
- API requests must go uniformly through `useApi.js`.
- Subpath deployment: `vite.config.js` reads `VITE_BASE_PATH` (default `/`) into `base`; `useApi.js` exports `apiUrl()` and applies the runtime prefix only at the 6 fetch boundaries (cache keys / `invalidateCache` stay on raw `/api/...` paths). Any code that bypasses `useApi.js` (bare `fetch('/api/...')`, `el-upload :action`, blob download helpers) must wrap its URL with `apiUrl()` — the wrapped sites are LoginView login fetch, `WordImportDialog.vue` Word import upload `:action`, `App.vue` Word export fetch / `_blobDownload` / project-import fetch, ProjectInfoTab project-logo GET / profile PUT / org-preset logo GET, `OrganizationManagementView.vue` org-preset logo GET / PUT, and `DocxScreenshotPanel.vue` `pageUrl()`; the complete inventory is owned by cross-stack §9 — guarded by `tests/basePathDeployment.test.js`. Desktop packaging requires a default root-path build.
- Field preview and HTML rendering must uniformly reuse `useCRFRenderer.js`.
- Field display rules should preferably reuse `formFieldPresentation.js` to avoid repeating presentation-layer concatenation logic in components.
- The checkbox field (`复选`) remains outside `isChoiceField()` and codelist flows: pass `label` and optional `checkbox_label` through every renderer adapter, render `□checkbox_label` with `✔` default fallback (`CHECKBOX_DEFAULT_TEXT`), and clear its type-specific text when switching to another field type. It uses the regular `label | control` layout and creates no aCRF option-level OID annotation.
- Ordering interactions should preferably reuse `useOrderableList.js`, `useSortableTable.js`, and `useOrdinalQuickEdit.js`; drag sorting and direct ordinal jumps must keep filter-disabled behavior and the shared `排序保存失败，已恢复` recovery semantics aligned.
- User-facing fuzzy search boxes should reuse `searchRanking.js`; components pass the base ordered list and candidate text extractor, and must preserve legacy concatenated candidates where previous behavior matched combined fields such as unit `code + symbol` or option `code + decode`.
- `FormDesignerTab.vue` design note display has moved from the right-side aside to the canvas header / designer-section-title summary + tooltip path; only the visits preview dialog (`VisitFormPreviewDialog.vue`) still keeps the original aside style.
