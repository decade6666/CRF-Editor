# backend Module Notes

> Last updated: 2026-10-16

## Module Responsibilities
- Provide REST APIs and the frontend static resource entry point.
- Manage SQLite data models, lightweight migrations, and connection configuration such as WAL / foreign keys.
- Execute template `.db` import, project `.db` import / full-database merge, Word `.docx` import, Word export (eCRF / aCRF), and database export.
- Provide user authentication, admin APIs, regular-user password change, project isolation, and the desktop release entry point.
- Provide the weekly AI-assisted source-release automation: standalone CLI `scripts/weekly_release.py` (plan / bump-versions / tree-hash / publish) plus `.github/workflows/weekly-release.yml` — release-only Actions exception, default-off, no executable assets, no production deploy.

## Key Entry Points
- `backend/main.py`: creates the FastAPI app, registers routers, configures exception handling and security headers, validates configuration at startup, creates upload directories, initializes the database, and starts/stops the in-process recycle-bin cleanup background task; `should_enable_reload()` disables uvicorn hot reload when `CRF_ENV=production` (production runs are managed by systemd via `deploy/install-service.sh`).
- `backend/app_launcher.py`: PyInstaller desktop entry point, injects the packaged static directory, starts Uvicorn, opens the local browser, and manages the system tray.
- `backend/src/background_jobs.py`: in-process asyncio background jobs; currently hosts the recycle-bin cleanup loop, re-reads config each round, and honors `CRF_DISABLE_BACKGROUND_JOBS` for test isolation / explicit disable.
- `backend/src/config.py`: configuration loading, caching, and atomic updates; `config.yaml` is located in the project root, and production prefers `CRF_*` environment variables (except the recycle-bin cleanup policy, which intentionally stays file-only so the admin UI reflects runtime truth).
- `backend/src/database.py`: database engine, SQLite PRAGMA, Session, and column-level lightweight migrations. The reserved-admin healing logic now lives in `src/services/admin_bootstrap_service.py` (`heal_reserved_admin_account`), called from `init_db()`; `database.py` keeps only the lightweight migrations.
- `backend/src/dependencies.py`: dependencies for authentication, database sessions, project permissions, and admin permissions.
- `backend/src/rate_limit.py`: single-node in-memory rate limiting, used for login, password change, and high-cost import endpoints.
- `backend/src/utils.py`: common utility functions such as path safety validation.
- `backend/scripts/weekly_release.py`: standalone weekly-release CLI (no runtime-app imports). Deterministic version arithmetic (bare three-part semver, minor/patch only), net-product-diff eligibility policy, bounded + secret-scanned AI payload (openai/anthropic), closed-schema decision parsing, `Release-Plan-V1` commit envelope with digest, atomic `main`+tag push, pending-release recovery. Configuration comes only from `RELEASE_AI_*` environment mappings; gitleaks gates every outgoing/persisted surface and fails closed. See README「每周 AI 辅助发布」.

## Core Directories
- `src/routers/`: APIs for authentication, admin, projects, visits, forms, fields, dictionaries, units, import/export, settings, and the read-only template field search. Dictionary/unit reference endpoints support opt-in `include_unplaced=true` for delete preflight; reference and codelist-option mutation routes enforce project ownership before resource lookup.
- `src/services/`: heavy logic for authentication, user management, import, export, database export, ordering, project cloning, project import, shared field-instance copy, recycle-bin cleanup planning, project size estimation, shared hard-delete/purge, AI review, Docx screenshot cache, shared temp-resource lifecycle (absolute temp paths, streaming upload writes, worker-completion draining), field cleanup, column width planning, field rendering, Word table parity comparison, Word table-of-contents page number pre-calculation, read-only template field indexing, shared dictionary/unit reference queries, the shared copy-name ladder helper (`unique_name.py`), reserved-admin healing (`admin_bootstrap_service.py`, moved out of `database.py`), and more.
- `src/models/`: Project, Visit, Form, VisitForm, FieldDefinition, Field, FormField, CodeList, CodeListOption, Unit, OrganizationPreset, User.
- `src/schemas/`: request/response structures for projects, visits, forms, fields, field profiles, dictionaries, units, organization presets, admin routes (`admin.py`), template import (`template_import.py`), plus shared validation helpers (`_common.py`, OID charset validators).
- `src/repositories/`: database access wrappers for the base repository, projects, field definitions, and form fields.
- `tests/`: pytest cases for authentication, admin, recycle-bin cleanup policy/background-task isolation, permissions, project isolation, batch-delete isolation, import/export, streamed DB/DOCX upload limits and cleanup, temp-resource expiry, async worker draining and threadpool handoff, Word import temp-file ownership/expiry, synthetic multi-type Word import parsing, ordering, configuration, WAL, rate limiting, column width planning, performance FK indexes, form orientation, Word import contract, Docx screenshot failure semantics, Word table parity, reference-query/delete-guard contracts, codelist option authorization, startup migrations, template field index, form copy style retention, Word export error semantics, unhandled-exception logging, copy-name ladder contracts, order-index migration, admin bootstrap service, template-import error mapping, order/sequence service parity, and more.
- `scripts/`: template database migration, Docx template field comparison, preview/export table field parity comparison, date format normalization, and the weekly release CLI (`weekly_release.py`, covered by `tests/test_weekly_release*.py`).

## Router Overview
- `routers/auth.py`: login, current user, regular-user password change, and authentication error semantics.
- `routers/admin.py`: admin user management, password reset, batch project operations, recycle bin, recycle-bin cleanup policy, and dry-run cleanup preview.
- `routers/projects.py`: project CRUD, project copy, Logo upload/read/delete, database import/export. The project batch-delete request is now the shared `schemas/project.py::ProjectBatchDeleteRequest` (`project_ids`, 1..500), serving both `POST /api/projects/batch-delete` and `POST /api/admin/projects/batch-delete`; an empty list or more than 500 ids → 422 (Pydantic) before any DB work.
- `routers/visits.py`, `routers/forms.py`, `routers/fields.py`: CRF structure maintenance.
- `routers/codelists.py`, `routers/units.py`: dictionary and unit maintenance; their reference endpoints accept opt-in `include_unplaced=true` for delete checks while preserving default edit-impact responses.
- `routers/import_template.py`, `routers/import_docx.py`: template library and Word import preview/application.
- `routers/export.py`: Word export.
- `routers/settings.py`: configuration read/save and AI connectivity tests.
- `routers/template_fields.py`: read-only template-library field index (`GET /api/template-fields`); authenticated-user only (no project scope), project-independent template read with optional-column probes, and path-free error responses (400 未配置模板库 / 404 文件不存在 / 400 路径无效 / 400 `TEMPLATE_INCOMPATIBLE` / 500).

## Service Overview
- `auth_service.py`, `user_admin_service.py`: password hashing, JWT version invalidation, reserved admin account, and user management.
- `import_service.py`, `project_import_service.py`, `docx_import_service.py`: template, project library, and Word import. `docx_import_service.py` mints 32-hex temp ids, uses `build_owned_filename` for owner-bound `{temp_id}_u{user_id}_p{project_id}_{name}.docx` uploads, and uses `build_owned_db_filename` for fixed `{temp_id}_u{user_id}_p0_upload.db` import files. Docx lookups go through `get_owned_temp_path` (same user + same project only), and `discard_upload` removes the file, screenshot cache, and AI task. `temp_paths.py` is the single source for the absolute `backend/uploads/docx_temp` directory shared by the Word import and screenshot services; `upload_streaming.py` streams upload data to exclusive 0600 files with chunked reads/writes and size checks; `await_drain.py` waits for shared worker operations to finish before propagating request cancellation. Normal `.db` imports unlink their file in the request `finally`; `purge_expired_uploads` sweeps `.db` crash leftovers alongside `.docx` files after 24 hours. `save_temp_file` has been removed.
- `template_field_index_service.py`: `build_template_field_index` reuses `ImportService._open_template_session` to read the template `.db` without any project scope; `PRAGMA table_info` probes optional legacy columns (`project.deleted_at`, `form.code`, `form_field.label_override`, `field_definition.checkbox_label`), whole-table raw `text()` reads are filtered in Python (no ORM, no long `IN` lists), 标签 fields / log rows / soft-deleted projects are excluded, and definitions with identical displayed attributes merge into one entry (accumulated `sources` with `form_code` = whitespace-cleaned `form.code`, `null` for missing column / blank value / library-only; deduped `label_aliases`); session closed in `finally`, filesystem path never returned to clients.
- `export_service.py`: Word document rendering and export (eCRF / aCRF). The former whole-form landscape renderer was removed (`_classify_form_layout` only ever returns `legacy` / `mixed_landscape`); option labels come from the single helper `field_rendering.get_option_labels`; structure rows (`_add_log_row` / `_add_label_row`) share `_fill_structure_row_cell` with log-only shading/recolor; normal and inline tables share the `_render_control_into_cell` dispatch ladder; `_add_forms_content` is a thin orchestrator over `_render_mixed_landscape_form` / `_render_legacy_form` (+ `_render_legacy_group`). Database export no longer lives here — see `database_export_service.py`; `ExportError` and `_EXPORT_ERROR_CODES` stay defined here (Word path + `main.py` handler).
- `database_export_service.py`: SQLite snapshot/prune database export (`export_full_database`, `export_project_database`, `export_user_projects_database`, `_vacuum_sqlite_file`, `_validate_form_field_schema`), moved verbatim out of `export_service.py`; imports `ExportError` / `_EXPORT_ERROR_CODES` from `export_service` (one-way dependency, no cycle).
- `project_size_service.py`: per-project estimated-size calculation for recycle-bin display and cleanup decisions; includes the `ROW_OVERHEAD_BYTES` tuning knob and logo-file byte accounting.
- `project_purge_service.py`: shared irreversible project purge helper (ORM graph delete) reused by routes and background cleanup. `purge_project()` only performs `delete` + `flush` and **returns** the Logo relative file name; the caller must `commit()` successfully and only then call `logo_storage_service.delete_file(PROJECT_NAMESPACE, rel)` — the single Logo deletion policy (path validation + warning-only failures) shared with org presets — so a failed commit leaves the recycled project with its logo intact, a killed process at worst leaves an orphan file, and a tampered/unsafe stored name can never crash deletion.
- `recycle_bin_cleanup_service.py`: age/size cleanup policy resolution, dry-run plan building, and per-project transaction execution semantics.
- `width_planning.py`: backend column width planning, sharing the fixture contract with frontend `useCRFRenderer.js`.
- `word_table_parity.py`: reads browser preview JSON and exported `.docx` table text to generate strict parity reports.
- `toc_pagination.py`: optionally invokes LibreOffice headless rendering to export documents and uses `pypdf` to read PDF outline page numbers; when unavailable or failed, returns an empty result while `export_service.py` keeps non-empty fallback page-number text and relies on Word field update for correction.
- `order_service.py`: ordering write logic for visits, forms, fields, and related entities. The `order_index` and `sequence` families share private implementations parameterized by column (`_get_next` / `_insert_at` / `_delete_and_compact` / `_reorder_batch` / `_compact_after_batch_delete`); the deliberate asymmetries (only the order family self-heals NULLs via `_ensure_initialized`, and the direction/sign differences) are passed as explicit flags. `move_to` / `move_to_sequence` keep separate bodies (park-at-0 vs min/max offset).
- `unique_name.py`: `first_free_name(first, numbered, is_taken, start)` — the shared copy-name ladder loop (return `first` if free, else the first free `numbered(start), numbered(start + 1), …`). The suffix template, numbering position, and start index stay with each caller, so the `_copy` / `(副本)` / `(恢复)` / `_导入` / `（导入）` / `_IMP` ladders stay verbatim.
- `admin_bootstrap_service.py`: `heal_reserved_admin_account(engine)` — reserved-admin healing moved out of `database.py`; `init_db()` calls it between `_ensure_form_field_rowid_compatibility` and `_move_orphan_projects_to_recycle_bin`. Imports `get_config` / `is_production_env` and `hash_password` / `has_usable_password_hash`; does not import `src.database`.
- `project_clone_service.py`: project deep copy and Logo linkage.
- `form_field_copy.py`: shared field-instance copy used by project clone, template import, and form copy; `COPIED_ATTRS` is derived from the `FormField` table columns minus `CALLER_SUPPLIED_ATTRS` (`form_id` / `field_definition_id` / `order_index`) and `NEVER_COPIED_ATTRS` (`id` / `created_at` / `updated_at`), so a column added to the model is copied by default and no single copy site can silently drop a display attribute again.
- `docx_screenshot_service.py`: Word import screenshot cache lifecycle and failure state for unsupported runtimes, with PDF-outline-first form page detection plus form-name-signature-based page-range caching; the auto-mode no-backend error is platform-aware (`_no_backend_message`, `_is_windows`), and `main.py` lifespan runs a non-blocking startup self-check via `log_render_backend_status` (WARNING + install hint when missing, INFO when ready).
- `ai_review_service.py`: AI import suggestion/review calls.
- `field_cleanup_service.py`: structural cleanup for orphaned label field definitions after delete flows.
- `field_definition_reference_service.py`: shared codelist/unit reference query builder; default mode preserves historical placed-field edit-impact rows, while `include_unplaced=true` includes library-only definitions so delete preflight matches the 409 guards.
- `field_rendering.py`: field rendering helper logic.

## Database and Compatibility
- SQLite connections enable `foreign_keys=ON`, `journal_mode=WAL`, `busy_timeout=5000`, and `synchronous=NORMAL`.
- `src/database.py` handles compatibility migrations for historical databases, including backfilling `code`, `order_index`, `design_notes`, `annotation_positions`, `checkbox_label`, color markers, `owner_id`, soft delete, ordering fields, and user password-related fields. The `order_index` / `sequence` backfill is driven by `_ORDER_BACKFILL_TARGETS` through the shared `_backfill_null_order(conn, table, group_column, order_column)` helper (identifiers come only from that tuple).
- `project.deleted_at` is written with naive local `datetime.now()` and the recycle-bin cleanup cutoff must use the same naive-local convention; comparing against an aware UTC datetime will shift the effective cutoff by the local UTC offset.
- Background jobs must not reuse `get_session()` / `get_read_session()` request-scoped dependencies; they must build their own `Session(get_engine())`, and the recycle-bin hard-delete loop commits one project at a time to keep WAL write-lock windows short and avoid half-deleted project graphs on crash.
- The `form_field` structure uses a canonical column-set rebuild strategy to ensure field instance structures are consistent after old databases are upgraded.
- `form.annotation_positions` is stored as JSON text and must keep one shared validation contract across CRUD, form copy, project clone, project `.db` import, **template library import**, and aCRF export; external `.db` input with invalid JSON / invalid reserved keys must fail closed instead of being silently accepted. Mixed-column legacy templates (e.g. with `paper_orientation` but missing `annotation_positions`) must stay read-only compatible — probe the column and fall back to raw SQL single-column reads rather than ORM whole-row SELECT.
- The main entry point uniformly converts common validation errors, unique constraint conflicts, import errors, and export errors into stable JSON responses.

## Security Behavior
- In production, `/docs`, `/redoc`, and `/openapi.json` are disabled, and `CRF_AUTH_SECRET_KEY` is required.
- In production, JWT TTL must not exceed 60 minutes.
- Login, password-change, and high-cost import endpoints use single-node in-memory rate limiting.
- In production, if no available reserved admin exists, startup automatically repairs or creates one based on `admin.bootstrap_password` / `CRF_ADMIN_BOOTSTRAP_PASSWORD`; if missing, startup fails fast.
- Admin-created users must be assigned an initial password at creation; password reset invalidates old JWTs immediately through `auth_version`.
- Project-scoped codelist reference reads and all five option mutations verify project ownership before resource access; option update/delete also verify codelist membership before looking up the option. Regressions in `tests/test_codelist_option_authorization.py` cover foreign-owner 403/no change and owner status-code compatibility.
- Logo files are managed under `upload_path/logos`; only safe bitmap formats are allowed, and project copy / hard delete synchronously handles the corresponding files.
- Word-import temp uploads are owner-bound: every temp-id endpoint validates `^[0-9a-f]{32}$` (422 otherwise) and resolves the id only for the uploading user in the uploading project; a foreign id is answered byte-identically to a missing one (no existence disclosure, deliberately not 403). Word uploads and streamed `.db` project imports share the absolute `backend/uploads/docx_temp` directory; `.db` names use a fixed stem with no user-controlled path component and are removed in the request `finally`, while the hourly 24h sweep also covers crash-left `.db` files. Word uploads expire after 24h via the hourly background sweep.
- `template_path` must be located within a whitelisted directory and be a `.db` file; the template library import path (`src/services/import_service.py`) only allows read-only access. Old templates missing `form.paper_orientation` fall back to `auto` through read-only probing; adding columns, running migrations, or implicitly creating databases on the source template library is forbidden. The template field search (`template_field_index_service.py`) reuses `_open_template_session` (whitelist + compatibility + `PRAGMA query_only`) and never includes the filesystem path in API errors.
- Unhandled exceptions caught by `security_headers_middleware` are logged first as an ERROR with the full traceback on the `src.main` logger (`未处理异常 <METHOD> <PATH>`) and then answered with the unchanged 500 `{"detail": "内部服务器错误"}`; only the method and path are logged, never request bodies or headers.

## Import/Export and Column Width Contracts
- Word export table row height uses `FORM_TABLE_ROW_HEIGHT_CM = 1` as the `AT_LEAST` lower bound; cell paragraphs use `SINGLE_LINE_HEIGHT_PT = 15.6` fixed line spacing and `CELL_VPAD_PT` top/bottom spacing to support single-line 1cm rows, while multi-line content grows naturally without clipping.
- Word export table of contents uses a hybrid pre-rendered mode: `_add_toc_placeholder` only writes the "Table of Contents" title (SimSun, 12pt, bold, centered) and records an anchor; `_add_toc_heading` adds a unique `_Toc` bookmark for each heading and collects entries; `_populate_toc` runs after `_add_forms_content` and uses `_build_toc_entry` to generate each entry as a pre-rendered paragraph with bookmark hyperlink + `PAGEREF` field. **The first entry is merged into the TOC field start (`begin → instrText → separate`), and the last entry is merged into the outer `end`**, making all entries the field result between `separate→end` — therefore there is no blank line between the "Table of Contents" title and the first entry, it is visible and clickable with zero clicks, and Word replaces the whole field on update without duplication. Entry text is written in SimSun via `_apply_raw_run_font`; `_ensure_toc_styles` idempotently injects `TOC1/2/3` paragraph styles (the default template only has `TOCHeading`; otherwise dangling `pStyle` falls back to the default font and makes the layout look unlike a table of contents).
- Real table-of-contents page numbers (server side): `export_project_to_word(bake_toc_page_numbers=True)` calls `_bake_toc_page_numbers`→`services/toc_pagination.py` after saving, renders the docx to PDF with LibreOffice headless, reads the PDF outline (generated from Heading 1) to obtain page numbers for each heading, and writes them back into each entry's PAGEREF result text (`_toc_pageref_values` records `w:t` nodes by heading text). Each entry starts with a non-empty fallback page number, so if LibreOffice/pypdf is unavailable, fails, or returns an incomplete outline, the exported document keeps visible fallback page numbers and logs the fallback while retaining PAGEREF fields and `updateFields=true` for Word correction (LibreOffice and Word pagination may differ by one page). Unit tests avoid spawning LibreOffice for each case; the dedicated `test_export_toc_bakes_real_page_numbers_with_libreoffice` validates baked page numbers when LibreOffice is installed, otherwise it skips. Dependencies: `pypdf` (`requirements.txt`) + system LibreOffice (`soffice`, optional).
- `word_table_parity.py` uses `extract_docx_form_table_fields` with `_has_field_codes` to skip paragraphs containing field codes, avoiding TOC entries interfering with form title extraction.
- Vertical single-choice/multiple-choice option paragraphs must write `w:snapToGrid=0` via `export_service._disable_snap_to_grid` (`_render_vertical_choices` calls it for every option paragraph). Under section-level `w:docGrid type=lines linePitch=312` (15.6pt line grid), Word's default `snapToGrid=1` snaps paragraph `space_before=0` for the first option and `VERTICAL_OPTION_GAP_PT=3pt` for the remaining options to the full-line grid, rendering as "the gap from the first item to the second item is too large"; after disabling snapping, exact spacing is preserved and all option gaps are consistent. Any change to `docGrid` / vertical option spacing must synchronize the `snapToGrid` assertions in `test_export_unified.py` and `test_export_paper_orientation.py`. `_render_vertical_choices` also writes a `w:tcMar` top/bottom cell margin (`CELL_VPAD_PT`≈6.37pt → 127 twips) so options do not sit flush against the cell border lines; this is orthogonal to paragraph spacing (option paragraphs keep `space_before=0`/gap, rows still grow with content — see `test_export_vertical_choice_rows_can_expand_without_extra_option_padding`). Choice markers `○`/`□` are forced to SimSun for every run that contains them in `_set_run_font` (covers structured / string / default-value paths); a color-only `_set_run_font` re-color (text_color) no longer resets the run font.
- Word export normal table column widths are content-driven: `export_service._build_form_table` calls `width_planning.plan_normal_table_width(fields, available_cm=14.66)`, and width-aware text fill-lines use `compute_fill_line_char_count`.
- Column width planning (constants, CJK code-point ranges, inline-header floor, shared fixture + generator): cross-stack §1; fill-line char-count estimator and strict preview/export parity: cross-stack §5; checkbox `复选`: cross-stack §8. The backend entry points are `width_planning.plan_normal_table_width` / `compute_fill_line_char_count` and `word_table_parity.py`.
- Template import OID contract: `import_service.py` copies the source `code` verbatim (whitespace-stripped) for form / codelist / unit, mints `generate_code(PREFIX)` only when the source is empty, and dedupes colliding OIDs inside the target project with the `_IMP` ladder (`_resolve_import_code` / `_make_unique_code`, shared by all three entities). No charset re-validation on import — `OID_PATTERN` applies only at Create/Update schema boundaries, consistent with `project_clone_service` / `project_import_service`. The unit/codelist **reuse** branches (symbol match; name + option signature match) must never overwrite the target's existing OID.
- Template import execute response: `_do_import`'s summary carries `imported_form_ids` — the actual target-project `Form` ids in creation order (length equals `imported_form_count`; zero imports yield `[]`) — and `ImportExecuteResponse.imported_form_ids` exposes them additively with a fresh per-response `default_factory=list`, so legacy constructors and old clients stay compatible (`tests/test_template_import_selection.py`).
- Word export error semantics: `ExportService.export_project_to_word` re-raises `ExportError` (never `return False`), and `routers/export.py::export_word` deletes the temporary `.docx` and re-raises it with a warning log, so `main.py`'s `export_error_handler` answers HTTP 400 with `{detail, code}` (e.g. `EXPORT_DATA_INCOMPATIBLE` for invalid aCRF `annotation_positions`). Other export failures stay 500 with the generic 「导出失败，请稍后重试或联系管理员」; the frontend already renders the backend `detail`, and no specific export error may be swallowed into the generic failure path again.
- Form copy must preserve field-instance display attributes: project clone, template import, and `POST /api/forms/{form_id}/copy` share `services/form_field_copy.py::copy_form_field` instead of hand-written `FormField(...)` literals. Callers keep their own foreign-key remap and ordering semantics; every other column (including `bg_color` / `text_color` / `label_bold` / `label_font_size`) is copied from the model column list, and a new `form_field` column must stay covered by `COPIED_ATTRS` (guarded by `tests/test_form_copy.py`).

## Development Conventions
- Layering: `routers -> repositories/services -> models/schemas`.
- New or changed backend code must pass `ruff format --check .` (format-only config; no lint rules are enabled). The one-shot format commit is registered in the repo-root `.git-blame-ignore-revs` so `git blame` skips it after `git config blame.ignoreRevsFile .git-blame-ignore-revs`.
- Put heavy logic in `services/`, keeping the interface layer lightweight.
- Data structure evolution is maintained by lightweight migrations in `src/database.py`.
- API responses should primarily be stable JSON; error messages should preferably return Chinese `detail` values that can be displayed directly.
- Form `paper_orientation` sync set and validation: cross-stack §7.
- `form.annotation_positions` sync set and validation: cross-stack §6.
- Checkbox field (`复选`) sync set: cross-stack §8.
- When modifying authentication, admin, rate limiting, project isolation, import paths, or Logo handling, security tests need to be supplemented in sync.
- When modifying import/export or column width planning, backend tests, frontend contract tests, and root/module-level documentation need to be updated in sync.
